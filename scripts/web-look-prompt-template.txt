## 出力（Markdown。以下の見出しをこの順で必ず書く）

### 1. サイトマップ
グローバルナビの項目を**実際のラベル文字列そのまま**列挙する。階層があれば入れ子で書く。
各ページが何を担っているか1行ずつ。ナビに出ていないがフッターにあるページも書く。

### 2. ページ共通のシェル
- ヘッダー: 高さ / 固定かどうか / ロゴの位置 / CTA の有無と文言 / モバイルの開き方
- フッター: 何段構成か / サイトマップを何項目露出しているか / 会社情報の粒度
- パンくず: 有無、表記、置かれている位置
- 下層ページのページヘッダ帯: 有無、高さ、背景（画像か単色か）

### 3. トップページの構成
セクションを上から順に列挙。各セクションについて
「役割 / 主要素（見出し・本文・画像・ボタン）/ 画面に占める高さの目安」を書く。

### 4. 下層ページの構成
下層2ページそれぞれについて同様に。**トップとの作り込みの差**を必ず明記する
（同等か、下層が明らかに簡素か）。

### 5. ビジュアルシステム
- 配色: メイン / アクセント / 背景の3系統を **16進数の実測値** で
- タイポ: 見出しと本文の書体系統（明朝/ゴシック/丸ゴシック）、和欧混植の有無
  - **主見出しとセクション見出しの実サイズを px で**（PC / モバイル）。
    「大きめ」ではなく「PC 96px / SP 40px」と書く
  - **英語表記の使い方**。参照サイトが英語をどこに置いているか
    （大見出しそのものが英語か、日本語見出しの上下に小さく添える英語ラベルか、
    ナビやボタンが英語か）。原文をそのまま引用する。
    日本語だけが詰まって見える面を、英語がどう逃がしているかを書く
  - **見出しの改行位置**。何文字目で折り返しているか、意味の切れ目で切っているか。
    1文字だけが次行に落ちている箇所があるならそれも書く（真似しないため）
- 写真: 何を撮っているか（人物 / 製品 / 現場 / 抽象）、寄りか引きか、点数
  - **角丸の有無と半径(px)**、縦横比、並べ方（何列・間隔px・高さを揃えているか・
    ずらしているか）。「美しく並んでいる」ではなく寸法で
- 図形・装飾: 円、線、三角、矢印などの幾何パーツの有無。
  **何が・どこに・いくつ・どのくらいの大きさで**置かれているか。
  それらが動くなら、どう動くか（広がる / 回る / 遅れて出る）
- 余白: セクション間の空きが詰まっているか広いか

### 6. モーション
上の実測データを踏まえ、**実装指示として書ける粒度**で。
- 支配的なリビール種別 / duration(ms) / easing
- **リビールの粒度**。セクション単位でまとめて出るのか、
  見出し→本文→画像と要素単位で順に出るのか。実測データの reveal 件数が
  ページあたり100件を超えるなら、それは要素単位（場合によっては文字単位）である
- **パララックス / スクロール連動**。実測の scroll_linked_count が 1 以上なら、
  何が動いているか（背景画像 / 図形 / 見出し）、スクロール量に対する移動量の差、
  固定（pin）しているか。**0件なら「なし」と明記する**
- **ホバー時の変化**。カード・リンク・ボタンに触れたとき何が起きるか
  （背景画像が出る / 色が反転する / 矢印が動く / 画像が寄る）。
  マウスを載せないと見えない表現は、静止キャプチャからは絶対に拾えない。
  **必ず実際にホバーして確かめること**
- 発火の仕組み（class トグルか、ライブラリか）
- ヘッダーのスクロール挙動
- ページ遷移演出の有無
- トップと下層で演出量に差があるか（数値で）
- prefers-reduced-motion への対応有無

### 7. 借りるべき点 / 借りてはいけない点
- `must_borrow`: 3〜5件。**構造やルール**として借りられるもの
- `do_not_copy`: 固有名詞・写真・コピーそのもの、および参照サイト自身の欠点
  （例: 下層が薄い、reduced-motion 非対応）

### 8. この業種の website に共通しそうな型
参照1件から一般化できる範囲で。断定できないものは「要追加観測」と書く。
