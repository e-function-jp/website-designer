## 実装側で使える語彙（これ以外を指示しない）

- レイアウト/部品: `src/components/` の既存コンポーネント。
  主なもの: SectionTitle / Card / Table / Timeline / Steps / Accordion / Badge / Alert /
  TextInput / Textarea / Stat / Carousel / Tab / Breadcrumbs / AnimatedCounter
- サイト共通シェル: `SiteLayout` + `_site.ts`（ヘッダー・フッター・パンくず・JSON-LD は自動）
- モーション: `ScrollReveal` の `animation` は
  `fade` / `fade-up` / `fade-down` / `fade-left` / `fade-right` / `zoom` / `blur` / `clip-up`。
  `duration`(ms) と `stagger`(ms) を指定できる。
  ヘッダー挙動は `none` / `solid` / `shrink` / `hide` の4択。
  ページ遷移は View Transitions の on/off。
- **スクロール連動**: `GsapScrollSection` の `animation` は
  `parallax` / `pin` / `scale` / `fade-up` / `fade-in` / `slide-left` / `slide-right`。
  `scrub` でスクロール量に追従、`start` / `end` で区間を指定できる。
  参照サイトに視差（背景と前景で移動量が違う、図形がゆっくり流れる）があるなら
  **必ずこれで指示する**。ScrollReveal は「出現」しか作れず、視差は作れない。
- **ホバー演出**: CSS で書く（部品不要）。カードやリンクに触れたときの変化
  （背景画像がフェードで出る、色が反転する、矢印が進む、画像が少し寄る）は
  指示しなければ実装されない。持続時間と easing まで書く。
- その他: `Marquee`（流れる帯）/ `AnimatedCounter`（数値のカウントアップ）/
  `CircleTextLink`（円形テキストリンク）/ `WaveDivider`（波形の区切り）
- 足りない部品は「新規コンポーネントとして切り出す」と明記してよい（推奨）

## 表現の作り込み（毎回必ず書く。書かなければ実装されない）

実装役はここに書かれたことしかやらない。「いい感じに」は通じない。
以下は**全ランで必ず埋める**こと。参照サイトに該当が無ければ「なし」と明記する。

1. **見出しの改行位置**
   `data-role="copy"` の見出しは、**どこで改行するかまで書く**。
   例: 「企画から改善まで、/ ひとつの設計で。」のように `/` で切れ目を示す。
   読点・助詞の切れ目で折る。**1〜2文字だけが次行に落ちる形にしない**
   （実測 2026-09-20: 「ひとつの設計で。」が「で。」だけ、
   「設計と改善の積み重ね。」が「ね。」だけ次行に落ちて品位を落とした）。

2. **見出しの寸法**
   主見出しとセクション見出しを **px で**（PC / モバイル）。
   参照サイトの実測値を下回らせない。小さくまとめると必ず平板になる。

3. **英語表記の設計**
   日本語だけで文字が詰まる面（セクション見出し、カード名、CTA 群）では、
   **英語を大きく・日本語を小さく添える**配分を指示する。
   参照サイトが英語で見せている箇所（例: 大きな英文キャッチ）は、
   同じ役割の英文を**こちらで作って**指示する（参照の原文は流用しない）。
   英語を使わないなら理由を書く。

4. **図形・装飾とその動き**
   円・線・三角・矢印などの幾何パーツを、**何を・どこに・いくつ・何pxで**。
   出現の仕方（広がる / 遅れて出る / 描かれる）と ms も書く。
   図形どうしをつなぐ線（円の後の三角形のライン等）は、
   欠けると流れが途切れるので省略しない。

5. **写真・カードの並べ方**
   列数 / 縦横比 / **角丸の半径(px)** / 間隔(px) / 高さを揃えるかずらすか。
   カードは**枚数が変わっても崩れない**条件（最小高さ、行内での折り返し、
   文字数の上限）まで書く。写真は必ずフェード系の出現を付ける
   （無いとチープに見える）。

6. **スクロール連動とホバー**
   視差の対象と移動量の差、固定（pin）の有無。
   ホバー時に何が起きるか（背景画像の出現など）。
   参照サイトの実測 `scroll_linked_count` が 1 以上なら、
   「なし」で済ませずに必ず割り当てる。

## 出力フォーマット（機械が読む。属性名と構造は厳守）

後段のスクリプトがこの HTML を属性で解析する。**属性名を変えたり省略したりしない。**
`#site-config` は <pre><code> に TypeScript を書いてよいが、
`#pages` は必ず下の形にする（<pre> で囲まない）。

```html
<section id="pages">
  <article data-page="/">
    <section data-section="hero">
      <h3>ファーストビュー</h3>
      <p data-role="purpose">…</p>
      <p data-role="layout">…</p>
      <p data-role="copy">…</p>
      <p data-role="components">…</p>
      <p data-role="animation">…（無ければ none）</p>
      <p data-role="image">…（無ければ none）</p>
    </section>
    <!-- セクションを続ける -->
  </article>
  <!-- ページごとに article を続ける -->
</section>
```

充足条件（満たさないとスクリプトが exit 1 にする）:
- `<article data-page>` が 4 件以上
- 全 `<section data-section>` に `data-role="animation"` がある
- `data-role="copy"` がセクション数の 8 割以上にある

## 出力（HTML 1枚。前後に説明文を書かない）

`<!doctype html>` から `</html>` まで。次の構造を必ず含める。

```
<section id="site-config">
  _site.ts にそのまま写せる内容。
  <dl> で name / tagline / theme(DaisyUI テーマ名。既定の light/dark/cupcake は禁止) /
  nav（ラベルと href の対）/ footerNav / organization / primaryCta / legalNav /
  motion(reveal / durationMs / staggerMs / header / pageTransition)
</section>

<section id="sitemap">
  作るページの一覧。<table> で「URL / ページ名 / 役割 / 想定本文量(文字)」
</section>

<section id="visual">
  <dl> で 配色(16進3色以上) / 見出し書体 / 本文書体 / 写真の方向性 / 余白の方針
</section>

<section id="pages">
  ページごとに <article data-page="/about/"> を作り、その中にセクションを
  <section data-section="...">
    <h3>セクション名</h3>
    <p data-role="purpose">このセクションの役割</p>
    <p data-role="layout">具体的なレイアウト。カラム数・画像の位置・寄せ・想定高さ</p>
    <p data-role="copy">実際に入れる日本語コピー（見出しと本文。ダミーテキスト禁止）</p>
    <p data-role="components">使う既存コンポーネント名、または新規切り出し案。
      **layout に書いた見た目と矛盾する部品を挙げない。** 実測 2026-09-18:
      layout は「細い横線と『組織診断 → 商談設計 → 現場定着』」と書いたのに
      components に DaisyUI の Steps（番号丸）を挙げ、5モデル中3つが番号丸で実装した。
      部品名を挙げるときは、その既定の見た目が layout の記述と一致するか確かめる。
      一致しないなら部品を挙げず、layout の記述だけを残す</p>
    <p data-role="animation">アニメーション指示。種別・duration(ms)・stagger(ms)。無ければ none。
      出現だけでなく、**スクロール連動（parallax / pin / scrub）とホバー時の変化**も
      ここに書く。どの要素にかけるかを名指しする（セクション全体か、見出しか、
      写真1枚ごとか）。実測でリビールが要素単位なら、まとめて1回かけない</p>
    <p data-role="image">必要な画像。無ければ none</p>
  </section>
  を並べる。
</section>

<section id="images">
  必要な画像を <figure> で列挙する。属性の形式は厳守（画像生成スクリプトが機械で読む）。
  <figure data-placement="top:hero" data-tags="工場,製造,現場,横位置" data-aspect="landscape">
    <figcaption data-prompt="生成プロンプト。被写体・構図・光・色調を具体的に。日本語で可。">
  </figure>
  placement は「{ページ}:{用途}」の形（例 top:hero / about:portrait / service:facility）。
  data-aspect は landscape / portrait / square のいずれか。
  1サイトあたり 4〜8 枚に収める（生成は課金されるため）。
</section>
```

## 守ること

- **全ページを書く。** トップだけ詳細で下層が1行、は不可。
  下層ページも `data-role="copy"` まで書く（実装者が文章を考えることになるため）
- `data-role="animation"` は全セクションに必ず置く。指示が無いなら `none` と書く
- モーションの数値は上の実測から写す。「フワッと」のような形容で書かない
- **トップと下層で演出量を揃える。** 参照サイトがトップだけ盛っていても真似しない
- 英語小見出しの連発（ABOUT / SERVICE / CONTACT の羅列）を指示しない
- 参照サイトの固有名詞・実在企業名を使わない
