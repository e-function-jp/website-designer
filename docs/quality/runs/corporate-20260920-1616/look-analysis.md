### 2. ページ共通のシェル

以下の寸法は、追加確認した **PC 1440×900px／SP 390×900px** を基準とする。セクション高さは動的描画による差を含む概数。`1画面＝900px`。

**ヘッダー**

- PCは画面上端に固定。初期高さ **100px**、スクロール後 **70px**。
- 背景は透明のまま。スクロールで隠れず、上下の余白を縮める。
- ロゴは左、主要ナビ4項目とCTA2個は右に横並び。
- CTAは **「資料ダウンロード」** と **「お問い合わせ」**。高さ **40px**、角丸 **3px**。
- 資料側は濃灰地、問い合わせ側は白地。通常リンクとの差を面で付ける。
- SPは高さ約 **64px**、左右余白 **25px**。右上の **24×24px** のメニューボタンから全画面ダイアログを開く。
- 実際に開いたSPメニューは **390×900px**。主要リンク5項目を縦積みし、その下にCTA2個を横並び、さらに補助リンク3項目を置く。背景は黒系、右上に閉じるボタン。

**フッター**

本文末尾の共通CTAと、会社情報フッターを分けて設計している。

- 共通CTA：**DOWNLOAD／CONTACTの2段**。各段はPCで約 **350〜390px**。
- フッター本体：視覚上 **4段**。
  1. ロゴ＋主要ナビ4項目。
  2. 3拠点の所在地。
  3. Pマーク取得情報。
  4. 補助リンク3項目＋著作権表記。
- 本体高さはPCで約 **884px**。サイトマップ相当のリンクは主要4＋補助3＝**7項目**。直前のCTA2項目を含めると9導線。
- 会社情報は拠点名、郵便番号、住所、建物・階数まで掲載。本社には電話・FAXを併記する。
- PCの拠点情報は3列、SPは縦積み。資本金・設立などはフッターに重複掲載せず、会社ページに集約。

**パンくず**

- 下層2ページともあり。
- 実表記は **「TOP・私たちについて」／「TOP・サービス」**。
- PCはページタイトル帯の右下、SPは大見出しの下に約 **80px** 空けて右寄せ。
- 本文内ではなく、ページヘッダーの構成要素として統一。

**下層のページヘッダー帯**

- 共通構造は「小さな日本語ラベル→大きな英語タイトル→パンくず」。
- PCは上端から約 **400px**、SPは約 **303px** までがタイトルとパンくずの領域。
- 「私たちについて」は設計作業の写真＋暗いオーバーレイ。写真領域と理念本文を連続させる。
- 「サービス」は **#F2F2F2** の単色背景。
- 背景を一律にせず、文字階層・配置・パンくずで共通性を保つ。

### 6. モーション

**支配的な演出と、実測値の解釈**

- 提供データの分類：zoom **69件**、fade **15件**、fade-up **10件**、fade-side **4件**。
- 主なdurationは **2400ms**、easingは **ease**。
- ただしzoomの多数は画像の拡大ではなく、**縦罫線の`scaleY(0→1)`、横罫線の`scaleX(0→1)`**。
- 罫線は縦が上端、横が左端を起点として伸長する。実装するなら線ごとに2400msを設定する。
- 会社ページでは **820ms** と **`cubic-bezier(0.22, 1, 0.36, 1)`** も検出。2400msを全要素へ一括指定する根拠にはしない。

**リビールの粒度**

| ページ | 検出数 | トップとの差 |
|---|---:|---:|
| トップ | 125 | — |
| 私たちについて | 110 | −15／約−12% |
| サービス | 195 | ＋70／約＋56% |

- セクション全体の一括表示ではなく、罫線、ラベル、見出し、本文、図形、業務項目ごとに動く。
- サービスの業務見出しには **Y方向24px→0px** の変位を確認。
- 円4個はPCで初期X変位が **0／−60／−120／−180px**。最終位置へ開く。
- 検出数には装飾罫線を含むため、125件を「125個の文章・画像」と解釈しない。
- 正確な要素間delayや文字単位のstaggerは未確定。件数だけから文字分解を指示しない。

**パララックス／スクロール連動**

提供データでは **6件**。ただし検出された変位には初期表示の終端も混ざるため、6つすべてを独立したパララックスとは断定しない。

追加確認できたもの：

- トップのコラージュ背景は **`position:fixed`＋transform**。
- スクロールY＝0→300pxで、背景の画面座標は約 **X＋20px／Y＋38px**。
- Y＝600pxでは約 **X＋220px／Y＋347px**、Y＝900pxでは約 **X＋419px／Y＋525px**。
- 通常の本文が上へ移動する一方、背景は画面内で右下へ移動する。一定倍率の単純パララックスではない。
- サービスの工程ナビはPCで **`position:sticky; top:120px`**。
- ScrollTriggerのpin件数は`null`。**ライブラリによるpinは未確認**。CSSのfixed／stickyとは分けて扱う。
- 残る連動対象と正確な進行曲線は要追加観測。

**ホバー：実際にポインターを載せて確認**

| 対象 | 変化 | 時間 |
|---|---|---:|
| ヘッダー「お問い合わせ」 | 白地・黒文字→**#424242地・白文字** | 300ms |
| トップ実績カード | 暗い被せがopacity **0→0.4**。案件文字が`translateY(100%)→0`で現れる | 300ms |
| 実績カード上のカーソル | 直径115pxの半透明円が出現し追従 | 個別duration未確定 |
| 丸矢印リンク | 文字下線が横へ伸びる。円内を塗り、矢印が右へ約10px抜け、別の矢印が左から入る | 主に300ms |
| メディア画像 | 画像が **scale(1→1.08)** | 倍率を確認 |
| 共通DOWNLOAD | 背景写真がopacity **0→1**。非選択のCONTACTはopacity **1→0.15**。罫線も抑える | 500ms |

共通CTAの写真は通常のフルキャプチャでは見えない。実装指示には、通常状態とホバー状態を別々に記載する。

**発火の仕組み**

- Lenisを3ページで検出。ただしLenisの存在だけでリビール実装まで説明できない。
- 観測対象ではclass追加なしでopacity・transformが変化する要素が多数。
- `data-*`属性による状態変更も使用。CTAでは`data-hover-active`、`data-hovered`、背景展開では`data-bg-expanded`がCSS条件になる。
- 「classを付ければ全演出が発火する」構成ではない。再実装ではスクロール検知、要素表示、ホバー、背景拡張を別の状態として管理する。

**ヘッダー・遷移・動作軽減**

- ヘッダーは **100→70px** に縮小。透明背景を維持し、非表示にはならない。padding・色のtransitionは **300ms**。
- 初回表示用のOpening要素あり。円の拡大と透明化を伴う。
- トップから会社ページへ実際に遷移した際、Opening要素は検出されなかった。**初回演出はあり、全ページ遷移で同じローダーが再生されるとは確認できない**。
- トップと下層は演出の種類を共有し、サービスでは内容量に応じて演出数が増える。
- `prefers-reduced-motion`は提供検証で **通常125件／軽減時125件、respected=false**。少なくとも計測対象の演出は軽減されていない。
- 借用実装では軽減設定時に罫線・本文を最終状態で表示し、スクロール連動移動、円の展開、カーソル追従を停止する。

### 7. 借りるべき点 / 借りてはいけない点

**`must_borrow`**

1. **トップを振り分け、下層を説明の場にする。** 会社への信頼、対応業務、制作実績を別ページで判断できる構造。
2. **共通シェルとページ固有の情報表現を分離する。** ナビ・タイトル階層・パンくず・CTAは統一し、会社は表、サービスは業務一覧と工程で展開する。
3. **サービス説明から実績へ接続する。** 抽象的な能力紹介の後に制作物を置き、裏付けを確認できるようにする。
4. **資料取得と相談を独立した共通導線にする。** 比較検討中の訪問者と依頼意向のある訪問者を同じ行動へ押し込まない。
5. **配色・罫線・余白・モーションをページ横断のルールにする。** 下層の情報量が増えても、同じサイトとして読める状態を保つ。

**`do_not_copy`**

- 社名、ロゴ、実績写真、取引先名、実績数値、コピーそのもの。
- `prefers-reduced-motion`非対応。
- SPの **5pxの工程英語ラベル**、小さな補助文字など、読める情報として機能しにくい寸法。
- 主見出しをSVGに固定し、改行や拡大表示への柔軟性を失う実装。特に「を実現」から始まる最終行。
- 添付で約1画面分に見える黒い演出領域を、目的のない空白として複製すること。
- ホバー時だけ案件情報を読ませる設計を、そのままキーボード・タッチ操作へ持ち込むこと。
- 「zoom 69件」を理由に、画像や文字へ69件の拡大演出を追加すること。
- 英語ラベルを装飾目的で量産すること。自社の情報分類に必要な箇所へ絞る。

### 8. この業種の website に共通しそうな型

広告・Web制作会社の企業サイトとして、この1件から仮説化できるのは次の構造。

- **会社の考え方→依頼できる業務→制作実績→相談先**を、どのページからでも確認できる。
- サービスページは「何ができるか」だけでなく、**担当範囲・工程・成果物**まで説明する。
- 会社ページは理念だけで終わらず、**法人情報・拠点・代表・取引先**で実体を裏付ける。
- 実績は専用一覧に集約しつつ、トップとサービス末尾にも抜粋して回遊を作る。
- **資料取得と問い合わせの二段階の受け皿**は、法人向けの比較検討行動に対応する型として検討できる。

一方、無彩色、大型欧文、長いスクロール、SVG見出し、立体図形、独自カーソルは、この参照サイトの表現選択であり業種共通とは言えない。**採用情報、ニュース、料金、業種別サービス、事例の成果指標をどの程度必須とするかは要追加観測。**
