05　モーションと操作

参照実測はfade-up 9件、fade-side 1件、duration最小・中央値・最大すべて900ms、ease。トップ10件／医院紹介0件／初診案内2件で偏りがある。本案では6ページすべて本文内4組に統一する。初期表示の見出し・写真・主要CTAは最初から見せる。

本文リビール
ScrollReveal、duration 900ms、stagger 0ms、delay 0ms、ease。fade-upはtranslateY(30px)から0、opacity 0から1。fade-leftはtranslateX(30px)から0、opacity 0から1。初回のみ。4組の内訳は各ページのanimation欄を正本とする。
発火
IntersectionObserver、rootMargin "0% 0% -100px 0%"、threshold 0。監視対象は無変形の外側。リビール対象は写真・見出しと短文に限定し、長大なセクション全体や入力欄を隠さない。
既存部品との差分
既存ScrollRevealは移動32px、独自easing、rootMargin -5%のためそのままでは一致しない。新規AobaRevealをScrollRevealのラッパーとして切り出し、既存部品に移動量・easing・rootMarginの任意設定を追加する。既定値は変えず、本サイトだけ本書の値を渡す。durationとstaggerは_site.tsから渡す。
ヘッダー
hide、transformの遷移480ms／ease。現行の退避開始条件y>160pxを保持し、下方向で退避、上方向で再表示。開始条件160pxは既存実装値であり参照の実測値ではない。PC退避量80px、モバイル72px。ページ上端、メニュー展開中、ヘッダー内フォーカス中は表示。縮小演出は追加しない。
低減・JS失敗
prefers-reduced-motion: reduceでは初期状態からopacity:1、transform:none、clip-path:none、transition:none。ヘッダーは表示固定、スクロールは即時。設定変更をページ表示中にも反映する。JS無効・初期化失敗でも本文を読めるよう、初期CSSは可視とし、監視開始成功後の画面外対象だけを準備状態にする。
ページ遷移
View Transitionsはoff。ローダーなし。スクロール連動1件は対象と移動量が未確定のため再現しない。stagger 0msは実測で間隔が確定していないための無効化指定。
操作状態
リンクは下線、ボタンは青／白の反転でhoverを示す。装飾の移動は追加しない。focus-visibleは3pxの青い輪郭と3pxの間隔、青背景では白い輪郭。全操作領域44×44px以上。アンカー位置はscroll-margin-top:104px。

08　実装の固定事項

部品の還元
AobaSplitHero、AobaPageIntro、AobaPhotoText、AobaPhotoPair、AobaTreatmentLinks、AobaRelatedLinks、AobaConsultationBand、AobaConsultationFlow、AobaConsultationDemo、AobaCta、AobaRevealを必要な粒度でsrc/components/sections/またはui/へ切り出す。既存部品を内包し、ページファイルへ複製しない。各ページで最低2件、サイト全体で最低6種類の既存コンポーネントを利用する。
予約デモの状態
入力→確認→終了の3状態。入力不備は先頭にrole="alert"の要約と項目リンク、入力にはaria-invalidとaria-describedby。エラー発生時は要約へ、確認時・終了時は各見出しへフォーカス移動。修正時は値を保持し、最初の項目へ戻す。終了時はフォームとメモリー上の値を消す。入力値はHTMLとして挿入せずtextContent相当で表示する。
デモの通信
送信先を作らず、入力内容をURL・ログ・アクセス解析へ入れない。外部フォーム、fetch、メール送信、永続ストレージは使わない。JS初期化前はfieldsetをdisabledにし、noscriptで「入力デモを使うにはJavaScriptを有効にしてください。治療案内はそのままご覧いただけます。」を表示。pageshow時に古い入力を復元しない。アクセス解析を追加しない。
画像配信
画像寸法とaspect-ratioを予約してレイアウト移動を防ぐ。トップ主写真はeager、fetchpriority high。各下層の導入写真はeager。画面外の写真はlazy。390／768／1440pxを想定したsrcsetを用意。写真を背景画像だけで実装しない。画像読込失敗時もキャプションと説明文が残る。
文字と順序
各ページh1は1件、以降h2→h3の順。CSSによる見た目の配置とDOMの読順を一致させる。装飾数字と矢印はaria-hiddenにし、必要な順序はリスト構造で表す。長いラベルは折り返し、320px幅でも横スクロールを発生させない。
リンク
全リンクをサイトのbase配下へ解決。ページ内リンクの対象idを必ず作る。href="#"、未作成ページ、架空の電話リンクは禁止。カード全体をリンクにする場合は中に別リンクやボタンを入れない。全ページの共通シェルから初診相談へ到達可能にする。
情報の制約
院長氏名、資格、学会、経歴、料金、治療期間、診療時間、休診日、交通、番地、支払方法、治療効果、患者の声は追加しない。実績3件は指定値のまま扱う。白い空白を地図・カレンダーの未実装領域として残さない。
確認条件
npm run build、npm run check:web、npm run check:catalogを実施。highゼロ、arch-component-reuseゼロ、ia-required-page-missingゼロを確認。320／390／768／1440pxで全6ページを確認し、見出しの欠け、写真の主題切れ、追従CTAによる遮蔽を修正。キーボードだけでメニュー・全リンク・入力・確認・修正・終了へ到達できることを確認する。
モーションの確認
通常時は各ページ4組、すべて900ms／stagger 0ms。下層を含む全ページを同条件で確認。低減設定とJS無効時に本文・リンクが初期表示されること、メニュー展開中とフォーカス中にヘッダーが退避しないことを確認する。
