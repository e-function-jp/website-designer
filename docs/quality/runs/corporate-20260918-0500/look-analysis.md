### 1. サイトマップ

グローバルナビは次の5項目。階層メニューではなく、同列のページ入口として配置する。

| 実際のラベル | ページの役割 |
|---|---|
| Projects | 制作実績の一覧。分野別に絞り込み、個別案件へ進む |
| About | 理念、制作姿勢、チーム、自主事業、会社概要を説明する |
| Service | 提供サービスを説明する入口。今回のキャプチャ対象外 |
| News | 更新情報の一覧。トップでは直近3件を抜粋する |
| Contact | 問い合わせの入口。ヘッダー内では他項目と同じ扱い |

ロゴはトップページへのリンク。フッターには上記5項目に加えて、次の4項目がある。

| 実際のラベル | ページの役割 |
|---|---|
| Our Inspirations | 書籍など、制作活動の背景にある参照物を紹介する |
| Recruit | 採用情報への入口 |
| Faq | よくある質問への入口 |
| Download | 資料ダウンロードへの入口 |

以上のラベルとリンクは[実サイト](https://nssg.jp/)で確認。キャプチャ対象外ページの詳細構成は未確認。

Projects配下には案件詳細があり、一覧内のカテゴリナビは `All / Branding / Typeface / Visual Identity / Product Design / Interactive / Graphic / Event` の8項目。グローバルナビの階層とは分けて扱う。[Projects](https://nssg.jp/projects/)

### 2. ページ共通のシェル

寸法は、元画像の幅1440pxを基準とする。位置・区間高は画像からの概算。高さ900pxを1画面とすると、全長はトップ約5.6画面、About・Projects約6.4画面。

**ヘッダー**

- 実測高191px、`position: fixed`、背景は透明。
- ロゴは左端から約80px、上端から約55px。幅約48px。
- PCナビは右側に縦積み。5項目を約31pxピッチで並べ、その右に2本線のメニューボタンを置く。
- 塗りつぶしのCTAはない。`Contact` も通常のテキストリンク。
- トップでは写真上に重なり、下層では本文と同じ無地背景上に重なる。
- モバイル用CSSでは縦積みナビを非表示にし、右上の2本線ボタンから別のナビ領域を開く構造。開閉の操作検証は未実施。

**フッター**

- 2段構成。上段は「ロゴ／主要ナビ／補助ナビ／SNS／所在地／著作権」、下段は書体切り替え。
- サイト内ページは9項目を露出。ロゴによるトップへの導線は別。
- SNSは4件。所在地は英文住所と地図リンクまでで、電話・代表者・資本金などはAboutへ集約する。
- 下段の `Typesetting` は `NSSG Serif` と `NSSG Grotesk` の切り替え。ページリンクではない。
- 上段と下段の間隔はCSSで112px。背景色を変えず、空白で本文と区切る。[共通CSS](https://nssg.jp/cms/wp-content/themes/NSSG/assets/css/styles.css?ver=1.19)

**パンくず**

- 提示された3ページには見当たらない。
- 下層の現在地は小さなページタイトルとナビの表示差で示す。制作先にそのまま踏襲せず、パンくずは追加する。

**下層ページのページヘッダ帯**

- 画像付きの独立した帯はない。
- 上端から約297pxの位置に `About`／`Projects` を左揃えで置く。
- 上端から本文開始まで約340〜400px。背景は本文と連続する白系。
- Projectsではタイトルとカテゴリナビを同じ横帯に配置する。

### 5. ビジュアルシステム

**配色**

JPEGの採色値とCSS指定値は区別する。背景の最多画素は3画像とも `#FAFAFA`。JPEG圧縮や描画処理があるため、CSS指定と完全には一致しない。

| 系統 | 確認値 | 用途 |
|---|---|---|
| メイン | `#202020`：CSS指定値 | 本文・主要リンク・下線 |
| アクセント相当 | `#656565`：CSS指定値 | 英文などの補助文字。固定の有彩色アクセントは見られない |
| 背景 | `#FAFAFA`：画像実測、`#FBFBFB`：CSS指定値 | ページ全体の白系背景 |

補助罫線は `#E7E7E2`、薄い文字は `#BBBBBB`。写真内の青・緑・茶・ピンクは案件ごとに変わり、UI共通色にはしない。[配色・書体のCSS](https://nssg.jp/cms/wp-content/themes/NSSG/assets/css/styles.css?ver=1.19)

**タイポ**

- 初期設定は和文明朝＋欧文セリフ。日本語は游明朝系、欧文は独自のNSSG Serif。
- 書体切り替え時には和文ゴシック＋NSSG Groteskへ変わる。
- ページ見出しは約18px、理念の日本語は20px程度。キャプチャ内には48〜80px級の大見出しを置かない。
- 本文の基準は13px、行高約2.307＝約30px。ナビ11px、補助情報9〜11px。
- 和欧混植あり。理念では日本語の下に英訳、会社概要では項目名・値を日英で対応させる。
- 太字の大きさより、配置・行間・段落間隔で階層を示す。

**写真・画像**

- トップ：メイン写真1枠、実績20枠、参照物4枠＝計25枠。実績には写真以外のロゴ・書体見本も含む。
- Projects：55枠。人物、商品、パッケージ、建築、印刷物、ロゴなどを同じ外形に収める。
- About：室内写真1枚＋隣接画像の一部、自主事業ロゴ3枠が見える。横方向の総画像数はキャプチャだけでは確定しない。
- 商品は寄り、人物や店舗は中景〜引き。異なる撮影距離を、共通の縦長タイルで統一する。
- タイルは約232×410px、縦横比は約1.77。画像同士の間隔は約32px。

**余白**

- 共通左右余白は約80px＝画面幅の約5.5%。有効幅は約1280px。
- 実績は「232px×5列＋32px×4間隔」で有効幅を埋める。
- 主要セクション間は概ね200〜260px。タイル間32pxに対し約6〜8倍の間隔を取り、セクションの切り替わりを示す。
- 本文を全幅に広げず、左ラベル用の空間を継続して確保する。

### 6. モーション

**リビール**

| ページ | 検出数 | 支配種別 | duration 最小／中央値／最大 | easing |
|---|---:|---|---|---|
| トップ | 38 | fade-up | 700／1000／1500ms | ease、ease-in-out |
| Projects | 11 | fade-up | 700／1500／1500ms | ease、ease-in-out |
| About | 11 | fade | 1000／1000／1000ms | ease-in-out |

- 提示された種別内訳はfade-up 24、clip-wipe 8、fade 6。合計38件でトップの検出数と一致するため、全ページ合計として扱わない。
- 設計に転用する基準は、本文・一覧の入口をfade-up 1000ms、Aboutの文章群をfade 1000ms、画像群を最大1500ms、基本easingを`ease-in-out`とする。
- 移動距離、遅延、発火閾値、再発火条件は未測定。実装案としては`translateY(16px) → 0`、`opacity: 0 → 1`、初回のみ発火と指定できるが、これは参照の実測値ではない。

**発火の仕組み**

- Lenisの存在とView Transitionsの使用を検出。
- Lenisの存在だけでは、リビールを同ライブラリで発火しているとは判断できない。
- スクロール関連の検出は9件。pin／scrubの値は`null`なので、有無は不明。
- ヘッダーのclassトグルは確認済み。一般のリビールがIntersection Observerか別方式かは未確定。
- 後工程ではIntersection Observerで共通classを付与する方式に整理できる。画像数と検出数は一致しないため、「画像1枚につき独立アニメーション」とは解釈しない。

**ヘッダー**

- スクロール前後とも高さ191px、上端0、背景透明。縮小も背景切り替えもない。
- スクロール後に`is-hidden`が付く。
- CSSではそのclassにより内部ナビを`opacity: 0`、`pointer-events: none`にする。外枠全体の非表示ではないため、実測の`hides: false`と両立する。
- ナビのopacity変化は500ms、`ease-out`。[ヘッダーCSS](https://nssg.jp/cms/wp-content/themes/NSSG/assets/css/styles.css?ver=1.19)

**ページ遷移・演出量・減速設定**

- View Transitionsは使用中。具体的な遷移時間や画面の切り替え方は未測定。ローダー候補は検出されていない。
- トップ38件に対し下層は各11件。トップは約3.45倍、差は27件。モーション量のページ間一貫性は実測上`false`。
- reduced-motion時も38件から変化せず、提示データでは非対応。
- 制作先では`prefers-reduced-motion: reduce`時に移動・クリップ演出を止め、内容を初期表示する。スムーズスクロールとページ遷移演出も減速設定に合わせる。

### 7. 借りるべき点 / 借りてはいけない点

**`must_borrow`**

1. **トップは抜粋、下層は目的別の全情報。** 実績20件→一覧55件、短い理念→会社情報という分担を維持する。
2. **画像一覧の部品をページ間で共有する。** 列数・比率・間隔を固定し、件数と分類機能でページの役割を変える。
3. **会社説明は左ラベル・右本文の位置を固定する。** 文章、番号リスト、表に変わっても読み始める位置を揃える。
4. **フッターで主要5ページ＋補助4ページを再提示する。** トップへ戻らず、別の目的へ移れるようにする。
5. **下層末尾に関連ページへの導線を置く。** 会社理解からサービス確認・実績確認へ接続する。

**`do_not_copy`**

- 社名、案件名、人物名、コピー、写真、ロゴ、独自書体ファイルそのもの。
- reduced-motion非対応と、トップに偏った演出量。
- 9〜11pxの補助文字や薄い文字色を、そのまま日本語主体の企業サイトへ適用すること。
- パンくずの省略。
- 一覧を画像だけに依存させること。案件名・担当領域はキーボード操作とタッチ環境でも確認できる形にする。
- 業務内容がラベルから分かりにくい英語ナビの無条件な移植。制作先では事業に即した日本語へ置き換える。

### 8. この業種の website に共通しそうな型

この1件から仮説化できる範囲は、ブランディング・デザイン制作会社のサイトである。art業種全体への一般化は避ける。

- **実績が第一の判断材料になる。** トップで代表例を見せ、一覧と案件詳細で担当範囲を確認する構造。
- **会社説明には理念・人・組織情報を分担させる。** 制作物だけでは分からない判断基準や依頼先の実体を補う。
- **自主活動や参照物が制作姿勢の補足情報になる。** 必須ページかどうかは要追加観測。
- **トップと一覧で実績部品を共有すると、掲載数が増えても構造を維持できる。**
- **主要導線を実績・会社・サービス・更新情報・問い合わせに分ける構成**は転用候補。ただし、採用・資料請求の重要度は会社規模と営業方式について要追加観測。
- 5列構成、明朝主体、小さい文字、約6画面の長さ、長いリビールはこの参照の選択であり、業種共通の型とは断定しない。
