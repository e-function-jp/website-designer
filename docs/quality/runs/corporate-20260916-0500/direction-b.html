07　実装・検証の確定条件

会社概要の導入に掲載する本文は次の文章を正本とし、設計上の注記を公開しない：「軌道セールス設計株式会社は、東京都港区に所在するBtoB営業支援・営業組織コンサルティング会社です。設立は2016年、従業員数は48名。中堅製造業とSaaS企業に向けて、再現性のある受注プロセスの構築を支援しています。」

  • 全ページに固有のh1と40文字以上のdescriptionを設定する。descriptionは各introの本文を要約し、未提供の事実を追加しない。トップはheroの本文を使用する。
  • SiteHeader・SiteFooter・パンくずはSiteLayoutから一度だけ描画する。サイト限定のシェル表現を拡張し、他のサンプルサイトへ影響を及ぼさない。
  • 全リンクに実在ページを指定する。空のhref、href="#"、未実装の採用・資料請求・事例詳細へのリンクを作らない。
  • 320・390・768・1440px幅、200%文字拡大で検証する。固定ヘッダー、下部CTA、開いたメニューが本文や入力フォーカスを隠さない。フォーカス対象にscroll-margin-top:112pxを設定する。
  • メニューはdetails/summaryを使用し、タッチ対象は最低44×44px。通常文字4.5:1以上、UI境界3:1以上のコントラストを確認する。リンクは色だけで識別させず下線または枠を持たせる。
  • フォームはブラウザー内の一時的な状態だけで処理する。ネットワーク送信、localStorage、sessionStorage、入力値を含むURL、解析イベントへの値送信を実装しない。表示にはtextContentを使用する。
  • フォームのlabelと入力idを対応させ、エラーをaria-describedbyで関連づける。エラー概要へフォーカスを移し、各エラーから対象欄へ移動できるようにする。確認結果はaria-liveで通知する。JavaScript無効時は「入力内容の確認にはJavaScriptが必要です。外部への送信は行われません。」を表示し、確認操作を無効にする。
  • 各ページの2群だけにScrollRevealを使う。通常、軽減設定、JavaScript無効、直接URL訪問、View Transitions後の各状態で全文の可視性を確認する。
  • 各ページで共通シェル以外のsrc/components/部品を2種類以上使用する。全体でSectionTitle・Table・Steps・Accordion・Badge・Alert・TextInput・Textarea・Statを使い、6種類以上を満たす。
  • 新規部品をExtractしてカタログに反映する。npm run build、npm run check:web、npm run check:catalogを実行。high、arch-component-reuse、ia-required-page-missingがゼロであることを確認する。
