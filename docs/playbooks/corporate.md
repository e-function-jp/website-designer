### 6. モーション

**支配的なリビールと時間**

- トップの検出92件：fade 55件、fade-up 10件、fade-side 3件、その他24件。
- fadeは全検出の約60%。zoom、clip-wipe、blur、lazy-blur-upは0件。
- 集計対象のdurationは最小・中央値・最大ともに **700ms**。
- easingは **`ease`** と **`cubic-bezier(0.165, 0.84, 0.44, 1)`**。
- 生データには0秒のスタイル変化や文字単位の変化もある。92件を92個の独立したコンテンツ演出、700msを全アニメーション共通値とは解釈しない。

**発火の仕組み**

- `.js-trigger` に **`.is-shown`** が追加されることを確認。
- `.js-fadeup`、`.js-shuffle`、`.js-shuffle__text` が存在。コンテンツの出現と見出しの文字演出を分けている。
- `.js-loopslider__content` の横方向transform変化も観測。
- GSAP 3.0.5、Lenis、Swiperを検出。ただし、各挙動と各ライブラリの対応は未確定。
- スクロール連動は3件。ScrollTriggerのtotal・pinned・scrubbedは未取得で、ピン留めやscrubの指定はできない。

後工程で再構成する場合は、出現対象に共通クラスを付け、表示領域への進入で状態クラスを追加する。基本はopacity変化700ms、移動を伴う要素は同じ時間と上記easingに統一する。移動距離・発火位置・再発火条件は未測定なので、参照の実測値として指定しない。

**ヘッダーのスクロール挙動**

- 実測対象はグローバルヘッダーではなく **`home-works__header`**。
- 高さ42px、`position: static`。top座標が1,397pxから−403pxへ移動。
- 縮小、背景変更、クラス切替なし。`hides: true` は通常スクロールで画面外へ出た結果と読むべきで、自動収納ナビの根拠にはならない。
- グローバルナビは画像上で本文に重なるが、固定位置の詳細は追加観測が必要。

**ページ遷移**

遷移ライブラリとローダー候補は未検出。専用のページ遷移演出は確認できないため、再構成時に必須要件としない。

**ページ間の演出量**

| ページ | リビール検出数 |
|---|---:|
| トップ | 92 |
| Works | 0 |
| CG Direction | 0 |

差は92件で、実測の `motion_consistent` はfalse。下層にもライブラリと22件のkeyframes定義はあるが、定義の存在は実行を意味しない。下層の「0件」もホバー等を含む全動作の不存在を意味しない。

**prefers-reduced-motion**

通常92件に対しreduce設定でも83件が残る。減少は9件、約9.8%にとどまり、実測判定は非対応。

再実装ではreduce時に自動横移動・文字演出・スクロール追従を停止し、リビール対象を最初から表示する。参照の非対応は継承しない。

### 7. 借りるべき点 / 借りてはいけない点

**`must_borrow`**

1. **トップの振り分けと下層の探索を分担する。** トップは抜粋＋一覧リンク、Worksは分類＋一覧＋ページ送りに集中させる。
2. **受託実績と自社作品を別階層にする。** 発注先としての実績と、自社で保有・展開する作品をナビから区別する。
3. **一覧と絞り込みで同じテンプレートを使う。** ヘッダ帯、分類UI、カード比率、フッターを固定し、結果だけを変更する。
4. **作品カードの情報順序を統一する。** 全面画像→作品名→分類タグの順で、比較に必要な情報を同じ位置に置く。
5. **フッターを第二のサイトマップにする。** 主要領域だけでなく分類・個別コンテンツへの近道を設ける。露出件数は自サイトの規模に合わせる。

**`do_not_copy`**

- 会社名、ロゴ、山型シンボル、作品名、キャラクター、写真、コピーそのもの。
- 英語ラベルの一律転用。対象企業の顧客が事業内容を理解できる日本語ラベルに置き換える。
- トップ92件・下層0件という演出量の落差と、reduced-motion設定でも83件が残る挙動。
- カテゴリー名・選択状態・件数が読み取りにくい絞り込みページ。固有見出しと現在地表示を追加する。
- 1件の検索結果に対して約1,520pxのフッターが続く比率。情報量に応じてフッターの密度を調整する。
- パンくずの省略、本文に重なるナビ、右端で切れるカテゴリー帯を無検証で再現すること。
- トップの大きな空白を、動的表示の途中状態か確認せず固定スペーサーとして実装すること。

### 8. この業種の website に共通しそうな型

この1件から仮説として抽出できるのは、映像・CG・広告制作会社の **作品を起点に会社を評価する情報設計**。

- **訪問経路：** トップの代表作 → 実績一覧 → 制作領域で絞り込み → 作品詳細 → 問い合わせ、という構成が成立しそう。ただし作品詳細から問い合わせへの接続は未観測。

### 5. ビジュアルシステム

- 配色
  - メイン：`#111111`。本文・見出し。
  - アクセント：`#000000`。6×6pxのグリッドドット、罫線、メニューアイコン。
  - 背景：`#F5F5F5`。全ページ、マーキー、フッター。
  - UIには色相を持つアクセントカラーがない。青、黄、緑などは写真内だけに限定する。

- タイポ
  - 欧文はTWK Lausanne系の`ls-350`／`ls-450`、和文は游ゴシック系。見出し・本文ともゴシック。
  - 下層H1/H2は最大75px、トップ領域見出しは60px、右側リンクは28px。ヒーローのワードマークはSVGをほぼ画面幅いっぱいに表示する。
  - 本文は下層で20px、行高1.75。本文幅は全幅にせず、5列中2列程度へ制限する。
  - `Company Philosophy`、`Our Value`、`人生をみがこう。`など和欧混植あり。英語は飾りではなく情報分類として使う。

- 写真
  - トップ：キャプチャ上6点。人物1、製品・素材1、水面1、製造／店舗空間2、抽象寄り写真1。ヒーローには未表示分を含む7枚の切替候補がある。
  - Philosophy：写真配置9点＋動画1点。雪、滝、樹皮、蒸気など自然の寄り／引きと、靴を結ぶ動作、走る人物、店舗空間を混在させる。
  - Profile：写真4点。店舗外観、店内什器、商品棚、関連ページ用の抽象写真。
  - 商品を白背景で並べるより、身体動作・自然表面・現場空間を組み合わせてブランド思想を補強している。

- 余白
  - 広い。1セクションが1.2〜4.5 viewportに達し、写真と文章の間に1〜3グリッドセル分の空白を置く。
  - 情報量の少ないトップも高さを詰めず、写真が切り替わるまでスクロール距離を確保する。

### 6. モーション

- 支配的なリビール
  - 集計上の支配種別は`fade`。設計された要素リビールはトップ0件、Philosophy 11件、Profile 3件で、下層では`fade-up`が支配的。
  - リビールのdurationは実測不能で`null`、検出easingは`ease`。参照値として任意のmsを補わないこと。
  - 明示的に測れるヒーロー画像切替は1200ms、`ease-in-out`。3秒ごとに次の背景へ切り替える。
  - 画像パララックスは固定durationを持たず、スクロール進捗へ`-10%`から`+10%`をscrub接続し、`ease: none`。

- 発火の仕組み
  - ヒーロー：`is-active` classのタイマー切替。
  - 写真：GSAP 3.12.2＋ScrollTrigger。`start: "top bottom"`、`end: "bottom top"`、`scrub: true`、pinなし。
  - 慣性スクロール：Lenis。duration 1200ms、指数減衰型easing、タッチではsmooth無効。
  - PhilosophyのStatement消失はGSAPでopacityをスクロール連動。写真マスクにはclip-pathのスクロール連動もある。
  - 最上部マーキーはGSAPで28秒の無限linear移動。

- ヘッダー
  - `position: fixed`。スクロール前後とも高さ121px、top 28px、透明背景。
  - 縮小、退避、背景色変更、class切替はいずれもなし。

- ページ遷移
  - Barba、Swup、View Transitions、ローダー候補は検出されず、ページ遷移演出なし。

- ページ間の演出量
  - トップ0件、Philosophy 11件、Profile 3件。最大差11件で`motion_consistent: false`。
  - 共通するのはLenis、マーキー、画像パララックス。コンテンツ演出量はページごとに揃っていない。

- `prefers-reduced-motion`
  - サイト全体として非対応。マーキーを停止するCSSだけはあるが、GSAPパララックス、Lenis、ヒーロー切替、動画を包括的に止めないため、実測判定は`respected: false`。

### 7. 借りるべき点 / 借りてはいけない点

`must_borrow`

- トップを長い説明ページにせず、`Company / Service / Information / Recruit / Store`の5領域へ振り分ける索引にする。
- 左に領域名、中央に代表写真、右に下位リンクという3点セットを全領域で反復する。
- 5列グリッドとドットをトップ・下層・フッターで共有し、ページが変わっても座標系を変えない。
- 下層を「大見出し＋写真」だけで終わらせず、PhilosophyはStatement／Concept／Vision／Value、ProfileはMessage／History／会社概要に分解する。
- 各下層末尾に`Related Content`を置き、隣接ページへ戻す。フッターだけに回遊を依存させない。

`do_not_copy`

- `EZOBOLIC`、`人生をみがこう。`、`Train Your Life`、製品名、会社沿革、写真、ロゴ、年輪シンボルそのもの。
- `Company`と`Profile`、`Laboratory`と`Lab`、`Information`と`News`、`Recruit`と`Recruitment`のように、表示場所で同一ページのラベルを変えること。
- 下層ページでパンくずを省略すること。
- トップ0件、Philosophy 11件、Profile 3件というモーション量の不均衡。
- `prefers-reduced-motion`をマーキーだけに限定し、パララックスや自動切替を残すこと。
- ヘッダーに明確な問い合わせCTAがなく、通常フッターにもサイトマップ・法務リンクがない構成。
- 28pxのマーキーへ長い住所を常時流し、重要なナビより高いz-indexで固定すること。

### 8. この業種の website に共通しそうな型

- スポーツ／ウェルネス系のD2C企業では、`ブランド思想 → 会社情報 → 商品 → 店舗 → 開発背景 → ニュース → 問い合わせ → 採用 → EC`という役割分担は流用可能。
- コーポレートサイトをECの代替にせず、信頼形成と事業理解を担わせ、購入は`Store`へ分離する型は一般化できる。
- Philosophyで情緒的な理由、Productsで具体的な商品、Stockistで購入場所、Profileで法人情報を説明すると、トップへ情報を詰め込まずに済む。
- 自社店舗や開発拠点を持つ企業では、`Stockist`と`Laboratory`を独立ページにする価値がある。店舗・研究設備を持たない企業への一般化は要追加観測。
- 自然写真、巨大な余白、ドットグリッド、年輪モチーフがスポーツ業種全体の型かは要追加観測。これは業種慣習より個別ブランド表現の比重が高い。
- 下層をトップ以上の長さと写真量で設計する傾向が同業他社にもあるかは、参照1件では断定できず要追加観測。
