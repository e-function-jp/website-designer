### 6. モーション

- **支配的なリビール**：`blur`。`inview` 要素へスクロール到達時に`move`クラスを付与し、ぼかしを解いて表示する。実測は全ページ **800ms**、主なeasingは `cubic-bezier(0.39, 0.575, 0.565, 1)`、一部 `ease`。

- **パララックス／スクロール連動**：実測 **5件**。主に背景・装飾画像と、日課表の視線誘導に使う。固定ピンは日課表の左見出しで、PCのみ `position: sticky; top: 5rem`。この固定見出しの横を、時刻カード群がスクロールする。スクラブ／ページ全体を固定する演出は検出されていない。
- **ホバー**：実装済みのPCホバー規則を確認できる。
  - 特集カードはカード全体と内部写真をともに **1.05倍**へ拡大、**500ms**・`cubic-bezier(0.215, 0.61, 0.355, 1)`。
  - ヘッダーナビは日本語・英語を1文字ずつ`span`化し、文字を順番に移動させる。
  - 丸矢印付きリンク、メニュー内特集バナー、画像カードも矢印または画像倍率を変える設計で、静止画だけで完結させない。
- **発火の仕組み**：jQuery InViewで`.inview`に`.move`を追加。Swiperは「写真ギャラリー」のみ。GSAP等のスクロールアニメーションライブラリは検出されていない。

- **ページ遷移**：あり。内部リンククリック時、本文を約 **500ms** でフェードアウトしてから遷移し、遷移先でフェードインする。

## 実装側で使える語彙（これ以外を指示しない）

  主なもの: SectionTitle / Card / Table / Timeline / Steps / Accordion / Badge / Alert /
  TextInput / Textarea / Stat / Carousel / Tab / Breadcrumbs / AnimatedCounter
- サイト共通シェル: `SiteLayout` + `_site.ts`（ヘッダー・フッター・パンくず・JSON-LD は自動）

  `fade` / `fade-up` / `fade-down` / `fade-left` / `fade-right` / `zoom` / `blur` / `clip-up`。
  `duration`(ms) と `stagger`(ms) を指定できる。
  ヘッダー挙動は `none` / `solid` / `shrink` / `hide` の4択。
  ページ遷移は View Transitions の on/off。

## 表現の作り込み（毎回必ず書く。書かなければ実装されない）

実装役はここに書かれたことしかやらない。「いい感じに」は通じない。
以下は**全ランで必ず埋める**こと。参照サイトに該当が無ければ「なし」と明記する。

1. **見出しの改行位置**
   `data-role="copy"` の見出しは、**どこで改行するかまで書く**。
   例: 「企画から改善まで、/ ひとつの設計で。」のように `/` で切れ目を示す。
   読点・助詞の切れ目で折る。**1〜2文字だけが次行に落ちる形にしない**
   （実測 2026-09-20: 「ひとつの設計で。」が「で。」だけ、
   「設計と改善の積み重ね。」が「ね。」だけ次行に落ちて品位を落とした）。

2. **見出しの寸法**
   主見出しとセクション見出しを **px で**（PC / モバイル）。
   参照サイトの実測値を下回らせない。小さくまとめると必ず平板になる。

3. **英語表記の設計**
   日本語だけで文字が詰まる面（セクション見出し、カード名、CTA 群）では、
   **英語を大きく・日本語を小さく添える**配分を指示する。
   参照サイトが英語で見せている箇所（例: 大きな英文キャッチ）は、
   同じ役割の英文を**こちらで作って**指示する（参照の原文は流用しない）。
   英語を使わないなら理由を書く。

4. **図形・装飾とその動き**
   円・線・三角・矢印などの幾何パーツを、**何を・どこに・いくつ・何pxで**。
   出現の仕方（広がる / 遅れて出る / 描かれる）と ms も書く。
   図形どうしをつなぐ線（円の後の三角形のライン等）は、
   欠けると流れが途切れるので省略しない。

5. **写真・カードの並べ方**
   列数 / 縦横比 / **角丸の半径(px)** / 間隔(px) / 高さを揃えるかずらすか。
   カードは**枚数が変わっても崩れない**条件（最小高さ、行内での折り返し、
   文字数の上限）まで書く。写真は必ずフェード系の出現を付ける
   （無いとチープに見える）。

6. **スクロール連動とホバー**
   視差の対象と移動量の差、固定（pin）の有無。
   ホバー時に何が起きるか（背景画像の出現など）。
   参照サイトの実測 `scroll_linked_count` が 1 以上なら、
   「なし」で済ませずに必ず割り当てる。

# AGENTS.md

AI coding agent 向け共通指示（GitHub Copilot / Claude Code / Cursor 等）。
`CLAUDE.md` は Claude Code 固有の追加指示として併存する。

## プロジェクト概要

Astro.js + DaisyUI/TailwindCSS による **website（多ページサイト）特化コンポーネントライブラリ**。
サイトギャラリーからの参照学習と静的品質チェックの二系統で、日本市場向けサイトの
情報設計と意匠を単調改善する。詳細は [README.md](./README.md)。

姉妹プロジェクト `../lp-designer` は LP（1ページ）特化。**知見の流用可否は
[docs/migration-from-lp-designer.md](./docs/migration-from-lp-designer.md) に整理済み。**

## 技術スタック（固定）

| レイヤー | 技術 | バージョン |
|---|---|---|
| フレームワーク | Astro.js | 6.0.8（固定） |
| CSS | TailwindCSS | 4.2.2（固定） |
| UI | DaisyUI | 5.5.19（固定） |
| ビルド | vite | ^7.3.1（`overrides` で固定） |
| 言語 | TypeScript | strict |
| ランタイム | Node | >= 22.12.0 |

caret を外しているのは意図的。vite 8（rolldown）で `@tailwindcss/vite` が
`Missing field 'tsconfigPaths'` を出しビルドできないため。

## 規約（website-designer 固有）

- **ページを書く前に `_site.ts` を書く**。全ページが `SiteLayout` を使う
- 1サイト = 1ディレクトリ束（`src/pages/sites/{type}/{model}-{stamp}/`）。
  ページ1枚だけのサンプルは website ではない
- サイト種別の `required_pages`（`scripts/site_categories.py`）を満たす
- モバイルファースト必須
- DaisyUI 既定テーマ（light / dark / cupcake）のまま完成扱いにしない
- 各ページで `src/components/` を最低2件、サイト全体で6種類使う（ベタ書き禁止）
- 下層ページには必ずパンくず。`href="#"` を残さない
- モーションは `_site.ts` の `motion` で一元管理。トップだけ盛らない
- `prefers-reduced-motion` を必ず尊重する
- `check:web` high ゼロ + `arch-component-reuse` ゼロ + `ia-required-page-missing` ゼロ
  + 参照の咀嚼が目視OK + AIテンプレ非該当 = 完成定義

## やってはいけないこと

- トップだけ作り込み、下層をナビとフッターだけの空ページにする
- 各ページにナビを手書きする（必ずズレる）
- グローバルナビに事業内容が読めない空ラベルを並べる
- 英語小見出しの連発（ABOUT / SERVICE / CONTACT）
- 紫グラデーション on 白背景 / Inter 常用などの**汎用AIテンプレ感**
- 事業と無関係なストック写真 / emoji を主ビジュアルにする
- ホスト名や repo 絶対パスをソースに直書きする（`.env` と `scripts/env_config.py` を使う）
- Extract をせずに出荷する
